# SMS Spam Lab

Reading this as: an experiment workbench for five MSc students, with a readable lab-notebook style. ENERGY 1 / RHYTHM 2 / MOTION 1.

The first job is to show how a text classifier works. The second is to make changes caused by training-data poisoning visible. This is a local research MVP, not a security product or a chatbot.

Use a warm white surface, near-black text and a deep teal action colour. Teal marks actions, not claims that a message is safe. Use system sans-serif typography to keep installation offline and text readable. No external fonts, imagery, invented stats, animated decorations or marketing sections.

Use one labelled view selector: Try a message, Run an experiment, Team handoff. A vertical selector reflows on small screens instead of squeezing long tabs. The message form is the focal point in the first view. The comparison and actual false negatives are the focal points in the experiment view. Data tables scroll within their container, never the page.

Use native Streamlit controls, visible labels, 44px minimum control height, a clear focus outline and real loading/error feedback. Short plain English throughout. Display training/test provenance and methodological limitations next to results. A probability is a model score, not evidence of message safety. Quarantine must not imply that all removed rows are malicious.

The design search returned children's typography and a newsletter template. These do not fit MSc experiment work; only its readability and minimal-chrome advice is retained. There are no subscribers, testimonials or AI-chat features.
